## 05 GPGPU / Warp intro (Lecture 15) — cram
Midterm 2 (Thu Nov 26 2026). At most 12 high-yield cards. L15 only (not L18).

1. [high] What is heterogeneous GPGPU (host vs device)?
   Full-mark: host CPU runs main program; GPU device runs kernels; data/kernels loaded on host then sent to device.
2. [high] Why are host–device copies a dominant cost?
   Full-mark: separate memory spaces; bus copy can dominate small problems; naive GPU port may be slower than CPU.
3. [high] What layout/work pattern fits Warp?
   Full-mark: flat contiguous buffers, uniform work per thread, enough work to amortize copies.
4. [high] Rules of `@wp.kernel`?
   Full-mark: static types; no return — write outputs into arrays; one-element body, one thread per element.
5. [high] What does `wp.tid()` do?
   Full-mark: per-thread element index for indexing input/output arrays.
6. [high] What do you pass to `wp.launch` for $N$ elements on Nvidia?
   Full-mark: kernel, `dim=N`, args in `inputs=` (order), `device="cuda"` (practice Q3).
7. [high] `device="cpu"` vs `device="cuda"`?
   Full-mark: CPU = single-thread serial/portable; CUDA = parallel on Nvidia GPU; same code/semantics.
8. [high] Host array prep / results?
   Full-mark: `wp.array`, `wp.zeros`/`zeros_like`, then `.numpy()` after launch.
9. [high] Warp vs Pthreads vs MPI memory model?
   Full-mark: shared vs message passing vs separate host/device with copies.
10. [high] Warp best-fit and pitfalls?
    Full-mark: large data-parallel maps; pitfalls = excessive copies, non-contiguous data, too-small problems.
11. [high] Kernel independence restriction?
    Full-mark: output must not depend on another thread’s output.
12. [high] addArrays: how are results written?
    Full-mark: store into `z[tid]`; kernels do not return values.
