Fundamentals of filtering: convolution
•In convolution, the calculation performed at a pixel location is a weighted sum of intensity 
values from a neighbourhood surrounding a pixel
•If a neighbourhood is centred on a pixel then it must have odd dimensions
•e.g. 3 × 3, 5 × 5, etc..
•Intensity values from a neighbourhood are weighted by coeﬃcients that come from a 
convolution kernel - also known as a mask, or a ﬁlter
•These are described as a matrix with dimensions that match the neighbourhood size

===== PAGE 8 =====
Neighbours
•A pixel p at coordinates (x, y) has four horizontal and vertical neighbours
•The coordinates are given by: (x+1,y), (x-1,y), (x,y+1), (x,y-1)
•This set of pixels is called the 4-neighbours
•Some of the neighbours of p lie outside the image if (x,y) is on the border of the image.

===== PAGE 11 =====
Kernels
•An omnidirectional kernel is one whose response is the same, whatever the direction in 
which intensity values vary
•A uniform kernel has coeﬃcients which all have the same weight
•A nonuniform kernel has coeﬃcients which have diﬀering weights

===== PAGE 12 =====
Kernel normalization
•In image processing, kernels (matrices) are typically normalized - the kernel 
coeﬃcients are divided by the sum of the coeﬃcients
•For readability, this scaling coeﬃcient is written outside the matrix
•In code, kernel coeﬃcients are often already scaled 
•This is done so that:
•The average value of an area with constant intensity would remain the same 
after ﬁltering - as it should
•To prevent introducing bias during ﬁltering - the sum of the pixel values in the 
original and ﬁltered images must be the same

===== PAGE 18 =====
The convolution process
•Place the centre of the kernel over a pixel, P, in the input image
•Multiply each pixel in the k × k neighbourhood by the appropriate ﬁlter kernel coeﬃcient 
superimposed on it
•Sum all the products
•Place the suitably normalized sum into the pixel position, P, in the output image

===== PAGE 19 =====
Image borders
•Along the borders of an image it is not possible to compute a convolution, because part of 
the kernel lies beyond the image.
•True of any neighbourhood operation
•The size of the region in which normal convolution is possible is dictated by the dimensions 
of the convolution kernel.
•e.g. for a 3×3 kernel: 1-edge border

===== PAGE 21 =====
Image borders
•For an image (x, y)MN the region to which a 3×3 kernel applies is (M-2)×(N-2) with an origin at 
(1,1)
•In general, the kernel origin is at (m2,n2) and dimensions of the image that can be processed 
by that kernel are (M-2m2)×(N-2n2) 
•e.g. for a 5×5 kernel, origin is at (2,2) and the "processable" image size is (M-4)×(N-4) 
•e.g. for a 7×7 kernel, origin is at (3,3) and the "processable" image size is (M-6)×(N-6)
•etc. 
•A number of diﬀerent strategies exist to deal with this problem

===== PAGE 22 =====
Image borders
Options
•No processing at the border
•Ignore those pixels for which convolution is not possible
•Several diﬀerent ways to ignore them
•Option 1: copy of input pixels
•Copy the corresponding pixel value from the input image wherever it is not possible to carry out 
convolution.
•The image will have a border of unprocessed pixels
•Option 2: truncation of the image
•Remove those pixels for which convolution is not possible.
•The resulting image is smaller than, and oﬀset relative to, the input image.
