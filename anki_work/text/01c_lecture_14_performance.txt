Flynn's taxonomy
•Flynn’s Taxonomy is used to classify computer architectures. 
•It describes the number of instructions and the number of data streams that a system can 
execute simultaneously. 
•There are four types of system: 
•SISD - single instruction, single data 
•SIMD - single instruction, multiple data 
•MISD - multiple instruction, single data 
•MIMD - multiple instruction, multiple data

===== PAGE 6 =====
Flynn's taxonomy - SIMD
•In traditional SIMD systems, all of the ALUs were synchronized and could not store 
instructions.
•They were tied to the controller. 
•This type of system was good for parallelizing simple loops that work on large arrays of data. 
•It was most useful for data parallelism but not much else. 

===== PAGE 7 =====
Vector processors
•An example of a SIMD system is the vector processor. 
•These operate on vectors (arrays) of data. 
•They use vector registers and perform operations simultaneously on their contents. 
•Vector length is ﬁxed per system but is normally between 4 and 256 elements, each of which 
is 64 bits. 
•The same operation is applied to all elements of the vector (SIMD). 

===== PAGE 8 =====
Vector processors
•Beneﬁts of the vector processor: 
•fast and easy to use
•compilers are good at identifying code to vectorize 
•compilers provide feedback on how to vectorize loops 
•high memory bandwidth
•unlike cached data, all loaded data is used 
•Disadvantages of the vector processor: 
•don’t work well with irregular data structures (i.e. anything other than arrays)
•are hard to scale - longer vectors aren’t very useful 

===== PAGE 9 =====
Flynn's taxonomy - MIMD
•MIMD systems (multiple instruction, multiple data) are general purpose parallel systems. 
•Independent cores each contain their own ALU
•Asynchronous processors operate at their own pace
•Can be shared memory or distributed memory systems.

Distributed-memory systems: definitions 
•Clusters are a collection of systems. They are often connected through a commodity network 
(ethernet). 
•Nodes in these systems (the computers) are normally shared memory systems. These are 
sometimes called hybrid systems because they contain both shared memory and distributed 
memory systems
•A grid is the same idea with multiple clusters spread over a large (geographic) area. They are 
a large and spread out collection of clusters. 
•Grid systems are often heterogeneous. This means the nodes may use diﬀerent types of 
hardware and operating systems.

Shared memory interconnects
•The two most common shared memory interconnects are the bus and the switch. 
•The Bus: 
•most common
•the communications path (wires) are shared by the devices connected to it 
•low cost and ﬂexible
•multiple devices can be connected to it for little cost as the number of devices using the bus 
increases, the performance will likely decrease
•a larger number of processors on a bus means more waiting to access memory

Speedup revisited
•Since the goal of parallelism is to improve performance we need a method to measure it
•In the ideal case, we measure speedup in a parallel program as:  
S = Tserial / Tparallel  where T is time. 
•Tparallel = Tserial / p, where T is time
•Run times depend on the input data size, but speedup is less dependent in it (diﬀerences get 
averaged away), so it is easier to talk about performance using speedup, rather than run-time 
•For the rest of the class, we will talk about what happens with the speedup in more realistic, 
non-ideal scenarios

Speedup properties
•As the number of processes (p) increases, the speedup should also increase, but the beneﬁt 
from each additional processor decreases.
•Adding the ﬁrst additional processor gives you more speedup than adding a second or third

•Eﬃciency is the share of work that each processor contributes

Amdahl's law
•Amdahl's law is another eﬃciency-related concept 
•In a nutshell, Amdahl's Law states that unless virtually all of a serial program is parallelized, 
the possible speedup is going to be very limited — regardless of the number of cores 
available.

===== PAGE 41 =====
Example
•We can parallelize 90% of a serial program.
•Parallelization is “perfect” regardless of the number of cores p we use (i.e. no overhead).
•Tserial = 20 seconds
•Runtime  of parallelizable part is  
 
0.9 × Tserial / p = 18 / p seconds  
•This means that all we can improve is the 18 seconds of parallelizable run-time

===== PAGE 46 =====
Example: Amdahl's law
•Amdahl's law means that for every ratio of parallelizable / serial work, we eventually hit a 
point where adding more cores / processors no longer oﬀers any beneﬁt
•Mathematically, the speedup approaches an asymptote 1 / a, where a is the serial part of the 
work
•For example
•Max speedup is 2, if we use a = 0.5 (50% parallelizable)
•Max speedup is 10, if we use a = 0.1 (90% parallelizable) 
•Max speedup is 20, if we use a = 0.05 (95% parallelizable) 
•Max speedup is 100, if we use a = 0.01 (99% parallelizable)

===== PAGE 49 =====
Using Amdahl's law
•You can measure the timing of the inherently serial portion for a variety of trial runs, compare 
it to parallel run times, and compute the % of program execution that is inherently serial
•You can then use this to establish the limits on the speedup in the problem you are trying to 
solve
•This will tell you the maximum number of "execution units" your program will beneﬁt from, so 
you can do cost/beneﬁt analysis and decide what sort of hardware / cloud compute 
capability you should buy
