===== SLIDE 2 =====
Reduction
•A reduction operator in parallel programming is used to combine elements of an array into a 
single result
•This kind of task happens frequently with large sets of data, e.g.
•adding all of the data
•multiplying all of the data
•ﬁnding the minimum or maximum value.
•We saw a reduction back in Lecture 2, when we combined partial sums computed during a 
parallel sum computation

Reduction and MPI_Reduce
•MPI_Reduce implements reduction in MPI 
•It allows multiple processes to perform an operation on a set of data and sends the results to 
one process.
•E.g. combine partial sums computed by individual processes into a single sum

===== SLIDE 9 =====
MPI_Reduce 
An example
•MPI_Reduce(&tmpVal, &sum, 1, MPI_DOUBLE, MPI_SUM, 0, communicator); 
•This will: 
•send all tmpVal (from each process) 
•to process 0
•add the tmpVals from each process and store the results in the variable sum 
•Notes:
•tmpVal is a double
•one value for tmpVal is sent from each process (not an array) 
===== SLIDE 10 =====
Collective communication
•This type of operation is called collective communication. 
•It involves all processes within a communicator. 
•This diﬀers from point-to-point communication, which occurs between individual processes 
and uses functions such as MPI_Send() and MPI_Recv().

MPI_Allreduce 
AKA Butterﬂy reduction
•The function call to MPI_Allreduce() looks the same as MPI_Reduce() but without a 
destination process.
•Since the ﬁnal result will be sent to all processes there is no need to specify a destination. 
•E.g.

MPI_Bcast() - broadcasting 
•Sending data from a single process to all others (in the same communicator) is broadcasting. 
•It is an easier method to send data to all processes than using multiple MPI_Send() calls.

===== SLIDE 18 =====
MPI_Bcast() - Example 3.6 
•All processes run the same code but rank 0 (the 4th parameter) send the values (1st parameter) to the 
other processes.  
 
void Get_input(int my_rank, int comm_sz, double* a_p, double* b_p, int* n_p) {  
 
 if (my_rank == 0) { 
  printf("Enter a, b, and n\n");  
  scanf("%lf %lf %d", a_p, b_p, n_p);  
 } 
 
 MPI_Bcast(a_p, 1, MPI_DOUBLE, 0, MPI_COMM_WORLD);  
 MPI_Bcast(b_p, 1, MPI_DOUBLE, 0, MPI_COMM_WORLD);  
 MPI_Bcast(n_p, 1, MPI_INT, 0, MPI_COMM_WORLD);  
} /* Get_input */

===== SLIDE 21 =====
MPI_Scatter() – distributing different data
•MPI_Bcast sends the same data to every process. 
•The natural next question is: what if each process needs a diﬀerent piece?
•The answer is the scatter operation which splits and distributes the data
•MPI_Scatter splits an array on one process and sends one chunk to each process in the 
communicator.
•Common use: process 0 reads an entire vector, then hands each process only the slice it needs 
to work on.
process 0:   1 2 3 4 5 6 7 8 
↓  
process 0:   1     process 1:   2     process 2:   3     process 3:   4...
===== SLIDE 22 =====
MPI_Scatter() signature
•MPI_Scatter(send_data, send_count, send_type,  
            recv_data, recv_count, recv_type, src_process,  
            communicator);
•send_data/send_count/send_type describe the full array, only meaningful on 
src_process.
•recv_data/recv_count/recv_type describe this process's chunk — every process, 
including the source, receives its own piece into here.
===== SLIDE 23 =====
MPI_Gather() – the reverse of scatter
•Gather collects one chunk from every process and assembles them into a single array on one 
destination process.
•Common use: every process computes a partial result; one process needs the whole 
assembled array (e.g., to print or write it).
process 0: 1 process 1: 2 process 2: 3 process 3: 4 ...  
↓  
process 0: 1 2 3 4 5 6 7 8
===== SLIDE 24 =====
MPI_Gather() signature
•MPI_Gather(send_data, send_count, send_type,  
      recv_data, recv_count, recv_type,  
           dest_process, communicator); 
•Same six-argument shape as Scatter, direction reversed
•every process supplies send_data 
•only dest_process's recv_data ends up populated with the assembled array.
